# 项目知识库扫描范围

> 本文档是「获取知识库」功能**项目层**扫描的权威规格：knowledge 插件
> （`packages/knowledge/src/scan.ts`）按本文档的分类→扫描源→提取规则实现。
> 配套文档：`docs/全局知识库扫描范围.md`（全局层）。
> 设计来源：《项目知识库.md》分类表，此处固化为可执行的扫描规格。

## 1. 扫描根

扫描在用户显式指定的**项目工作区**下进行（Remote 方法 `knowledge/generate`
的 `workspace` 参数；宿主平面没有单一「当前会话」，工作区必须显式携带）。
扫描根 = `<workspace>` 目录本身，所有路径均为相对该根的 glob。

## 2. 排除规则（所有分类统一执行）

| 排除项 | 说明 |
|---|---|
| `.git/`、`node_modules/` | 依赖与版本库，绝不扫描 |
| `.dsh/` | 插件自身落盘目录（知识/错题/草稿），避免自我循环 |
| `.env`、`*.env`、`*secret*`、`*credential*` | 含密钥/凭据，一律排除（只允许 `.env.example`） |
| 锁文件 | `pnpm-lock.yaml`、`package-lock.json`、`yarn.lock`、`npm-shrinkwrap.json` |
| 构建产物目录 | `dist/`、`build/`、`out/`、`coverage/`、`lib/`（源码包例外见下） |
| 二进制/超大文件 | 单个文件 > 256 KB 跳过；非 UTF-8 文本跳过 |
| 运行时状态 | `*.log`、`*.pid`、`*.socket`、`*.sqlite*`、运行时生成的 JSON（见 devices 分类说明） |

## 3. 分类 → 扫描源 → 提取重点

| 分类 `category` | 扫描源（相对 workspace 的 glob，按序去重） | 提取重点 |
|---|---|---|
| `architecture` | `README.md`、`AGENTS.md`、`docs/architecture*.md`、`docs/adr/**/*.md` | 模块划分、数据流、技术栈选型、架构决策 |
| `deployment` | `package.json`、`Dockerfile`、`docker-compose.yml`、`Makefile`、`.env.example`、`docs/deploy*.md` | 启动命令、依赖版本、端口映射、环境变量（示例）、服务拓扑 |
| `devices` | `docs/devices*.md`、`docs/devices/**/*.md`、`config/**/*.yaml`、`ha-config/**/*.yaml` | 实体 ID、类型、API 端点、传感器清单 |
| `conventions` | `AGENTS.md`、`CONTRIBUTING.md`、`.editorconfig`、`tsconfig.json`、`eslint.config.*`、`docs/conventions*.md` | 命名规范、代码风格、提交规范、目录约定 |
| `glossary` | `README.md`、`docs/glossary*.md`、`docs/domain*.md` | 业务术语、缩写、领域黑话、专有名词定义 |
| `decisions` | `docs/adr/**/*.md`、`docs/decisions*.md`、`docs/rfcs/**/*.md`、`CHANGELOG.md` | 选型记录、取舍背景、替代方案、时间线 |

规则：

- 一个文件命中多个分类时，**按上表行序取第一个**分类（README.md 归属
  `architecture`，不重复进 glossary/deployment）。
- `AGENTS.md` 归属 `conventions`（比 architecture 更强调约定），但其
  `## 架构` 等节仍全文进 body，分类只决定 `category` 字段。
- 同一路径只扫描一次；glob 匹配结果按字典序排序，保证输出稳定。

## 4. 提取规则（无 LLM，确定性提取）

每个扫描到的文件生成**一条**知识条目：

| 字段 | 取值 |
|---|---|
| `id` | 自动生成 `kb-YYYYMMDD-NNN`（当日序号递增） |
| `scope` | `project` |
| `workspace` | 本次扫描的 workspace（绝对路径） |
| `category` | 按第 3 节分类表（**映射**：条目 schema 仅允许 `convention/fact/decision/pitfall/lesson` 五类，映射规则见下） |
| `tags` | `[语义分类, 文件扩展名去点, 'scanned']`（如 `['architecture','md','scanned']`；**语义分类原样保留在 tags 首位**） |
| `title` | 相对 workspace 的路径（如 `docs/architecture.md`），README 用 `README.md` |
| `body` | 文件内容摘要：头部（首个非空行起至多 40 行）+ 全部 `##`/`###` 小节标题清单；总长上限 8 KB，超出截断并追加 `\n<!-- 内容过长已截断 -->` |
| `source` | 文件绝对路径（去重键：`source` + `scope` 相同则跳过，幂等） |
| `created` / `lastUsed` | 扫描当日日期 |
| `confidence` | `0.6`（扫描提取，低于人工写入的 0.8） |
| `status` | `raw` |

**分类映射**（语义分类 → 条目 `category`）：

| 语义分类 | 条目 category |
|---|---|
| `architecture` | `fact` |
| `deployment` | `fact` |
| `devices` | `fact` |
| `conventions` | `convention` |
| `glossary` | `fact` |
| `decisions` | `decision` |

> 语义分类不丢：除 `category` 字段外，原样写入 `tags[0]`，检索与筛选仍可
> 按语义分类进行（如 `tags: architecture`）。

跳过条件：文件为空、提取出的 body 为空、`source` 已存在同 scope 条目。

## 5. 输出

一次扫描返回 `{ scanned, generated, skipped, entries }`：

- `scanned`：符合扫描源且通过排除规则的文件数；
- `generated`：实际写入的条目数；
- `skipped`：跳过数（重复 source / 空内容 / 超限），含明细原因计数；
- `entries`：本次新生成的条目视图（供面板即时展示）。

## 6. 幂等与增量

- 以 `source` + `scope` 为幂等键：重复点击「获取知识库」不会产生重复条目；
- 文件内容变化后重新扫描会生成**新**条目（不覆盖旧条目，旧条目保留供
  人工整理/删除）；
- 人工编辑过的条目（改 title/body）不受扫描影响——扫描只新增，绝不
  覆盖或删除既有条目。

# 现要求:

排除目录：node_modules、.git、.dsh、dist、build
排除文件：.env（含密钥）、二进制文件
总容量上限：所有文件总字符数 ≤ 500000（约 125K token）
超出时按优先级截断，优先保留高优先级文件
单文件内容截断：超过 10000 字符的文件只取前 10000 字符（后续再做分块）
项目库扫 workspace 根目录；全局库扫 ~/.dsh/knowledge/ 下的配置和用户档案

# 事实提取器 

## 职责
把扫描到的文件内容分批送入 LLM，按 JSON Schema 提取结构化事实条目。

## System Prompt：

```text
你是一个专业的知识库提取引擎。你的任务是从给定的文本中精准提取事实知识，输出严格的 JSON 格式。

关键原则：
1. 只提取原文中明确存在的事实，绝不添加推断或编造
2. 每条知识独立完整，脱离上下文也能理解
3. 分类必须从给定列表中选择，不能自创
4. 输出必须是合法 JSON
5. 忽略临时性内容（日志、报错、注释、一次性讨论）
6. title 用简洁陈述句，不超过 20 字
7. facts 是 2-5 条独立的事实陈述，每条一句话
```

## User Prompt 模板：

```text
从以下文件内容中提取【{{CATEGORY}}】类别的事实知识。

分类说明：{{CATEGORY_DESCRIPTION}}

scope: {{SCOPE}}

提取规则：
1. 只提取稳定、可复用的事实
2. 每条知识必须能独立理解，不依赖上下文
3. title 简洁，不超过 20 字
4. facts 是 2-5 条独立事实
5. source 填来源文件路径
6. 不要添加原文没有的信息
7. 如果内容里没有该分类的事实，返回 entries: []

输出 JSON 格式：
{
  "entries": [
    {
      "title": "HA 服务地址",
      "facts": ["Home Assistant 运行在 http://192.168.1.100:8123"],
      "tags": ["ha", "deployment"],
      "source": "docker-compose.yml"
    }
  ]
}

待提取内容：
---
{{BATCH_CONTENT}}
---
```

## 分块策略
每批目标 8000 token（约 32000 字符）
单文件超了就按文件切块，每块带文件路径
每批可以包含多个小文件，只要总大小不超
批次间独立，按分类串行处理（避免同时发太多请求）

## 去重策略
用 title 小写做唯一键
同 title 合并 facts（Set 去重）
合并 tags
source 用逗号拼接多个来源

# 条目写入器

## 职责
把提取出的 KnowledgeEntry 写入磁盘，格式为 frontmatter + Markdown，这样 dsh 官方的 skill-filesystem provider 能自动发现。

## 目录结构

```text
项目库：<workspace>/.dsh/knowledge/
  ├── architecture/
  │   └── kb-project-architecture-xxx.md
  ├── deployment/
  │   └── kb-project-deployment-yyy.md
  └── ...

全局库：~/.dsh/knowledge/
  ├── user-profile/
  ├── environment/
  └── conventions/
```

## 文件格式

```text
---
id: kb-project-deployment-ha-service
title: "HA 服务地址"
scope: project
category: deployment
tags: ["ha", "home-assistant"]
source: "docker-compose.yml"
confidence: proposed
expires: null
created: 2026-08-21
updated: 2026-08-21
---

## HA 服务地址

- Home Assistant 运行在 http://192.168.1.100:8123
- 使用 docker compose 部署
- 容器名：homeassistant

**来源**: docker-compose.yml
```

## 写入规则
新增条目 → confidence 设为 proposed，等待人工确认
更新已有条目：
如果原有 confidence 是 confirmed，保留 confirmed（不覆盖用户确认）
如果原有 confidence 是 proposed，更新内容，保持 proposed
facts 合并去重，新值追加
updated 时间刷新
幂等：重复生成不会产生重复条目
绝不整体覆盖，保护用户已编辑的内容

# 关键约束与注意事项
所有文件操作通过 ctx.fs，不要直接用 Node fs。这样才能和 dsh 的文件系统服务、权限系统、沙箱集成。

LLM 调用用 ctx.llm.chat，通过 dsh 的模型服务统一调用，不要自己发 HTTP 请求。

提取必须用 response_format: { type: 'json_object' }，强制 JSON 输出，杜绝格式漂移。

temperature 设为 0.1，提取是确定性任务，低温度减少幻觉。

所有新增条目 confidence 都是 proposed，必须等用户确认后才进入 confirmed 状态。这是安全底线。

更新已有条目时绝不覆盖 confirmed 状态——用户确认过的知识是权威的，AI 不能推翻。

容量上限必须有：单批 8K token、总扫描字符 50 万、每分类文件数上限。防止一次生成烧掉大量 token。

幂等：重复调用 kb_generate 不会产生重复条目，相同 title 的条目会合并更新。

全局库的生成：V1 先只做文件扫描路径。引导式问答（user-profile 类）可以后续加。

错误处理：提取失败（JSON 解析失败、LLM 报错）时记录日志并跳过该批次，不影响其他批次。返回结果中包含失败统计。
